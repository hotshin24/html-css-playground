# 한국어 문구 전수 검사 및 용어 통일 요청

## 목적

앱에 노출되는 모든 한국어 텍스트를 검사해 어색한 표현을 고치고, HTML/CSS 용어를 통일합니다.

## 용어 원칙

**태그와 속성은 이름 그대로 씁니다. 풀어쓰지 않습니다.**

학습자가 실제로 검색하고 코드에 쓰는 말과 화면에 보이는 말이 같아야 합니다. "대체 텍스트"를 몰라서 검색하면 접근성 이론 문서가 나오지만, `alt`를 검색하면 바로 쓸 수 있는 문서가 나옵니다.

| 현재 (추정) | 변경 |
|---|---|
| 대체 텍스트 | `alt` |
| 최상위 제목 | `h1` |
| 목록 요소 | `ul`, `li` |
| 제목 계층 / 제목 단계 | 제목 레벨 (`h1`~`h6`) |
| 폼 컨트롤 | `input`, `select` 등 실제 요소명 |
| 레이블 | `label` |

**단, 문장 안에서 자연스러워야 합니다.**

```
어색: alt이 없습니다
자연: alt 속성이 없습니다

어색: h1이 2개 있습니다
자연: h1이 2개입니다
```

태그명 뒤에 조사가 붙을 때 받침 처리도 확인해 주세요. 이전에 숫자 조사 문제를 고치신 것과 같은 사안입니다.

**참고 자료**

- MDN 한국어판 (developer.mozilla.org/ko/docs/Web/CSS/Reference)
- poiemaweb.com

두 자료의 용어를 참고하되 그대로 따르지는 마십시오. MDN 한국어판은 번역 품질이 고르지 않고, poiemaweb는 표기가 통일되지 않은 부분이 있습니다. **판단 기준은 "한국 웹 개발자가 실제로 쓰는 말인가"입니다.**

## 검사 범위

### 1. 판정 실패 문구 (`lib/judging/`)

`type`별 고정 템플릿 전부입니다. 파라미터가 들어가는 자리의 조사 처리도 함께 봐주세요.

### 2. 엔진 상시 조건 힌트

`heading-single`, `heading-order`의 회차별 3단계 힌트입니다.

### 3. 화면 안내 문구

- 소스 등록 (업로드, 저작권 고지, 종횡비 초과 안내)
- 구역 편집 (병합, 분할, 이탈 경고, `warning` 표시)
- 학습 화면 (상단 바, 시도 횟수, 예시 공개 안내)
- 피드백 패널 (통과/실패/권장, 재확인, 낡음 표시)
- 저장 실패, 오류 메시지
- 자리표시 이미지 목록

### 4. AI 프롬프트 (`lib/ai/prompts.ts`)

**여기가 가장 중요합니다.** AI가 생성하는 `desc`와 `hints`는 매번 달라져서 전수 검사가 불가능하므로, 프롬프트에 용어 규칙을 넣어 생성 단계에서 통제해야 합니다.

2단계 프롬프트에 추가할 내용입니다.

```
조건 설명과 힌트를 쓸 때 HTML 태그와 속성은 이름 그대로 쓰십시오.

올바름: "반복되는 항목을 ul로 묶어야 합니다"
잘못됨: "반복되는 항목을 목록 요소로 묶어야 합니다"

올바름: "이미지에 alt 속성이 필요합니다"
잘못됨: "이미지에 대체 텍스트가 필요합니다"

학습자가 검색하고 코드에 입력하는 말과 같아야 합니다.
```

다만 **1단계 프롬프트는 예외입니다.** 구조 분석에서 태그명을 쓰지 못하게 한 절대 규칙이 있고, 그건 태그 선택이 학습자의 판단 영역이기 때문입니다. 이 규칙은 유지해야 합니다.

3단계(모범 예시)는 코드만 생성하므로 해당 없습니다.

### 5. README와 PRD

문서의 용어도 통일해 주세요. 다만 PRD는 설계 문서라 `list-grouping` 같은 내부 유형명은 그대로 둡니다.

## 검사 방법

**전수 검사입니다.** 한국어 문자열을 모두 추출해 하나씩 확인해 주세요.

```bash
grep -rn "[가-힣]" --include="*.ts" --include="*.tsx" . | grep -v node_modules
```

확인할 것입니다.

- 태그·속성을 풀어쓴 표현이 남아 있는가
- 조사가 어색한 곳이 있는가 (받침 처리 포함)
- 번역투가 남아 있는가 ("~되어집니다", "~에 대해", "~을 통하여" 등)
- 같은 대상을 다른 말로 부르는 곳이 있는가
- 존댓말 어미가 일관된가
