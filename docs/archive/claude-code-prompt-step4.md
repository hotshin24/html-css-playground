# HTML/CSS 학습 플레이그라운드 — 4단계 요청

## 범위

**실제 시안 검증과 배포**입니다. 지금까지 모든 검증은 더미 SVG 하나로 이루어졌습니다. 실제 웹페이지에서 무엇이 깨지는지 확인하는 것이 이번 단계의 목적입니다.

PRD §8.5에 남긴 항목들을 닫습니다.

## 순서

1. 실제 시안 검증 (JW Anderson, 패스트캠퍼스)
2. 통짜 모드 학습 흐름
3. IndexedDB 용량
4. Vercel 배포

**1번에서 문제가 나오면 그것부터 처리합니다.** 배포는 마지막입니다.

## 1. 실제 시안 검증

### 1.1 대상

| 시안 | 검증 목적 | 저장소 커밋 |
|---|---|---|
| JW Anderson | 폼(사이즈 선택, 구독), 캐러셀, 구역 11개 | 가능 (본인 작업물) |
| 패스트캠퍼스 | 구역 20개 초과, `warning` 발동, 오버레이 겹침 | **로컬만. 커밋 금지** |

패스트캠퍼스는 타사 페이지이므로 스크린샷을 저장소에 넣지 마십시오. 로컬에서 테스트하고 결과만 기록합니다.

### 1.2 확인 항목

**분석 단계**

- 구역 분할이 시각적 구분과 맞는가
- `bounds` 오차가 오버레이를 어긋나게 하는 수준인가 (더미 시안에서는 2px)
- 격자 평면 고정이 유지되는가 (행 계층을 만들지 않는가)
- `mainTitleSectionId`가 타당한가
- 구조 트리에 금지어(태그명, CSS 속성)가 섞이지 않는가
- 20개 초과 시 `warning`이 실제로 발동하는가

**조건 생성**

- 필수 조건이 화이트리스트를 벗어나지 않는가
- `layout-result`의 대상 단위가 반복 항목으로 잡히는가
- 캐러셀에서 조건이 어떻게 나오는가 — **판단이 필요한 지점입니다.** 화면에 3개만 보이지만 실제로는 6개일 수 있습니다. AI가 무엇을 보고 몇 개로 세는지 확인해 주세요
- `form-label`이 실제 폼에서 생성되는가 (JW Anderson)

**화면**

- 구역 20개 이상일 때 오버레이 이름표가 읽히는가
- 긴 시안에서 편집 화면 스크롤이 동작하는가
- 학습 화면 1열에서 해당 구역이 제대로 강조되는가

### 1.3 예상되는 문제

미리 짚어두는 것이지, 반드시 발생한다는 뜻은 아닙니다.

| 항목 | 예상 |
|---|---|
| 구역 수 | 20개 초과 시 구역별 모드가 학습 도구로 비현실적. 상한이나 안내가 필요할 수 있음 |
| 캐러셀 | 화면 밖 항목의 개수를 AI가 알 수 없음. `list-grouping` 기대값이 실제와 다를 수 있음 |
| 세로로 긴 시안 | `heightRatio`가 작아져 오버레이 조작이 어려움 |
| 이미지 용량 | 8000px 넘는 스크린샷의 리사이즈 후 크기 |

**문제가 나오면 원인을 세 갈래로 구분해 보고해 주세요.**

- 프롬프트 문제 (지시가 부족하거나 모호함)
- 판정 로직 문제 (엔진이 잘못 판단)
- 구조적 한계 (시안 이미지만으로는 알 수 없는 것)

세 번째라면 고치는 대신 PRD 비목표나 §8.5에 기록하는 편이 낫습니다.

## 2. 통짜 모드 학습 흐름

§8.2 재측정 때 통짜 모드로 등록은 했으나 학습을 끝까지 돌려보지 않았습니다.

- 구역 표시가 사라지고 시안 전체가 보이는가
- 결합 판정이 불필요한 상태에서 `heading-single`·`heading-order`가 정상 동작하는가
- 시도 소진 시 예시 공개가 동작하는가
- 실제 시안(JW Anderson)의 통짜 모드는 페이지 전체를 한 번에 작성하는 것이라 현실적인지

마지막 항목은 판단이 필요합니다. 구역 11개짜리 페이지를 통짜로 작성하는 것이 학습 흐름상 성립하는지, 아니면 통짜 모드에 시안 길이 제한이 필요한지 알려 주세요.

## 3. IndexedDB 용량

- 실제 시안 2~3개 등록 후 저장 용량
- 리사이즈·WebP 변환 후 실제 크기
- 브라우저 할당량에 근접하는 시점
- 용량 초과 시 동작 (F-05 저장 실패 처리가 여기에도 적용되는가)

용량이 문제가 되면 해상도 상한이나 소스 개수 제한을 검토해 주세요.

## 4. Vercel 배포

### 4.1 함수 실행 시간 (선행 확인)

**조건 생성이 50~60초 걸린다고 하셨습니다. 배포 전에 이것부터 확인해 주세요.**

Vercel의 함수 최대 실행 시간이 플랜에 따라 다릅니다. 로컬에서는 되는데 배포에서만 끊기면 원인 파악이 어렵습니다.

- 현재 플랜의 함수 타임아웃 한도
- `maxDuration` 설정으로 늘릴 수 있는 범위
- 한도를 넘는다면 대안 (스트리밍 응답, 구역별 분할 호출 등)

구조 분석은 15~18초라 여유가 있습니다.

### 4.2 배포

- 환경 변수 `ANTHROPIC_API_KEY` 설정
- 빌드 통과 (`prebuild` 스크립트가 리눅스에서 무해하게 통과하는지)
- 배포 환경에서 전체 흐름 1회 (등록 → 분석 → 편집 → 학습 → 판정)
- IndexedDB가 배포 도메인에서 동작하는가
