# HTML/CSS 학습 플레이그라운드 — 다크 테마 적용 요청

## 배경

PRD §1.4에서 다크 모드를 비목표로 두었습니다. 근거는 미리보기 영역이 사용자 CSS만 적용되므로 항상 밝은 배경으로 남아, 다크 UI 안에 흰 패널이 박히는 구성이 된다는 것이었습니다.

**이 제약을 없애지 않고 디자인으로 흡수하는 방향으로 진행합니다.** 미리보기 iframe은 그대로 두되, 그 바깥에 어두운 프레임을 둘러 브라우저 창처럼 보이게 합니다. 실제 브라우저도 흰 페이지를 띄우므로 자연스럽고, 코드 영역과 결과 영역이 시각적으로 구분되는 이점도 있습니다.

**PRD §1.4의 다크 모드 비목표 항목을 수정해 주세요.** 비목표에서 제거하되, 미리보기 영역을 다크로 만들지 않는 이유는 그대로 남겨야 합니다. 그 제약 자체는 유효합니다.

---

## 1. 절대 지켜야 할 것

**미리보기 iframe 내부에 어떤 스타일도 주입하지 마십시오.**

- 리셋 CSS 금지
- 다크 배경 주입 금지
- `color-scheme` 메타 주입 금지

학습자가 자기 CSS의 효과를 정확히 관찰해야 합니다. 이것이 §4.1의 전제이며, 4단계에서 실측으로 확인한 사항입니다(부모 Tailwind preflight 미유입).

판정용 iframe도 마찬가지입니다. 측정값이 달라지면 §8.2 결과가 무효가 됩니다.

---

## 2. 미리보기 프레임 (핵심)

3열 미리보기를 브라우저 창처럼 감쌉니다.

```
┌─ 어두운 프레임 ────────────────┐
│  ● ● ●                        │  ← 창 상단 바 (선택)
├───────────────────────────────┤
│                               │
│   iframe (흰 배경, 손대지 않음)  │
│                               │
└───────────────────────────────┘
```

| 요소 | 처리 |
|---|---|
| 프레임 배경 | 패널 색 |
| iframe 여백 | 프레임 안쪽에 패딩 |
| 테두리 | 얇게, 낮은 대비 |
| 모서리 | 둥글게 |
| 상단 바 | 넣을지는 판단해 주세요 |

**상단 바(신호등 점 3개)는 과할 수 있습니다.** 브라우저 창 은유를 명시적으로 드러내는 장점이 있지만, 학습 도구에 장식이 늘어나는 단점도 있습니다. 시안 열과의 균형을 보고 판단해 주세요.

**시안 열(1열)도 같은 처리가 필요한지 봐주세요.** 시안 이미지도 대개 밝은 배경이므로 같은 문제를 갖습니다. 두 열에 동일한 프레임을 두면 "이 둘은 참조 대상, 가운데는 작업 영역"이라는 구분이 생깁니다.

## 3. 색상 토큰

PRD §1.4에서 "색상은 CSS 변수로 정의하여 향후 도입 가능성을 열어둠"으로 적어두었습니다. 이미 변수로 되어 있다면 값만 교체하면 됩니다.

Claude 인터페이스의 다크 톤을 참고합니다.

| 역할 | 방향 |
|---|---|
| 배경 | 아주 어두운 뉴트럴. 순검정(#000) 아님 |
| 패널 | 배경보다 한 단계 밝게 |
| 본문 텍스트 | 순백 대신 약간 낮춘 회백색 |
| 보조 텍스트 | 본문보다 낮은 대비 |
| 강조 | 따뜻한 오렌지 계열 |
| 테두리 | 낮은 대비, 얇게 |
| 경고 | 기존 `--chrome-warning` 유지하되 어두운 배경에서 읽히도록 조정 |

**대비를 실제로 확인해 주세요.** 다크 테마에서 텍스트 대비가 부족한 경우가 흔합니다. 본문 텍스트는 WCAG AA(4.5:1) 이상을 확보해 주세요. 이 도구가 접근성을 가르치는 도구라는 점에서 자체적으로 지키지 않으면 앞뒤가 맞지 않습니다.

## 4. CodeMirror 테마

`lib/editor/theme.ts`의 토큰 색을 다크에 맞게 조정합니다.

- 태그, 속성, 문자열, CSS 속성명, 값이 서로 구분되어야 합니다
- 선택 영역, 커서, 활성 줄 배경도 함께
- 줄 번호는 본문보다 낮은 대비로

기존에 문법 하이라이팅이 "서로 다른 색"으로 확인된 상태이므로, 다크에서도 같은 수준의 구분이 유지되는지 확인해 주세요.

---

## 5. 나머지 화면

| 화면 | 확인 사항 |
|---|---|
| 소스 목록 | 카드, 상태 표시 |
| 소스 등록 | 폼, 업로드 영역, 저작권 고지 |
| 구역 편집 | **오버레이 반투명도 재조정 필요.** 밝은 배경 기준으로 맞춰진 값이 다크에서 다르게 보일 수 있습니다 |
| 학습 화면 | 상단 바, 에디터, 피드백 패널 |
| 피드백 패널 | 통과/실패/권장 구분 색 |
| `/dev/verify` | 검증 결과 표. 통과·실패 색 구분 |

구역 편집 화면의 오버레이가 특히 중요합니다. 시안 이미지 위에 얹히는 요소라 밝은 배경 위에서 조정된 값입니다.

---

## 6. 작업 방식

1. 색상 토큰 정의부터 잡고 확인받아 주세요
2. 미리보기 프레임과 시안 프레임
3. CodeMirror 테마
4. 나머지 화면

**각 단계에서 스크린샷으로 확인해 주세요.** 색상 작업은 검사로 잡히지 않습니다.

## 7. 요청

- 미리보기·판정 iframe 내부에 스타일을 주입하지 마십시오
- 대비 확인은 실제 값으로 해주세요
- 판단이 필요한 지점(상단 바 여부, 시안 열 프레임 등)은 질문해 주세요
- 커밋 메시지와 주석은 한국어
- 작업 후 §8.2 재측정을 한 번 돌려 판정 결과가 변하지 않았는지 확인해 주세요. `fixtures/aiRunsImproved.ts`로 API 호출 없이 가능합니다
