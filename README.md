# HTML/CSS 학습 플레이그라운드

웹 디자인 시안을 보고 직접 HTML/CSS를 작성하며 **시맨틱 마크업**과 **레이아웃 구현** 능력을 훈련하는 학습 도구입니다.

**https://htmlcss.choineiu.com**

시안을 등록하면 AI가 구조를 분석해 구역을 나누고 판정 조건을 만듭니다. 학습자는 구역 하나씩 코드를 작성하고, 확인을 누르면 조건 충족 여부를 판정받습니다. 틀리면 회차마다 구체화되는 힌트를 받고, 시도를 소진하면 모범 예시가 공개됩니다.

상세 사양은 [docs/PRD.md](docs/PRD.md)에 있습니다.

## 이 프로젝트에서 어려웠던 것

결과물만 보면 AI로 만든 학습 도구지만, 실제로 시간이 든 곳은 **판정이 정답을 오답으로 만들지 않게 하는 설계**였습니다.

### 정답 코드와 비교하지 않습니다

같은 시안에 대한 올바른 구현은 여러 가지입니다. 상품 목록을 `ul > li`로 짜든 `div > article`로 짜든, Flexbox를 쓰든 Grid를 쓰든 모두 맞습니다. 모범 예시와 코드를 대조하는 방식은 **정답을 오답으로 판정하는 오류를 반드시 만듭니다.**

그래서 판정은 코드 비교가 아니라 **조건 목록 충족 여부**로 합니다. 학습 도구에서 가장 큰 실패는 틀리지 않은 코드를 틀렸다고 말하는 것이라고 보고, 그 방향의 오류를 구조적으로 막는 데 설계를 맞췄습니다.

### 화이트리스트로 오탐을 구조적으로 차단합니다

AI가 자유롭게 조건을 만들면 "이 부분은 `section`으로 감싸야 합니다" 같은 것을 필수 조건으로 낼 수 있습니다. `div`로 감싸도 틀리지 않은데 말입니다.

필수 조건이 될 수 있는 유형을 **6가지로 고정**했습니다.

| 유형 | 검사하는 것 |
|---|---|
| `heading-order` | 제목 레벨을 건너뛰지 않았는가 (`h2` 다음 `h4`) |
| `heading-single` | 문서에 `h1`이 하나인가 |
| `image-alt` | `img`에 `alt` 속성이 있는가 |
| `list-grouping` | 반복 항목이 `ul`의 `li`로 묶였는가 |
| `form-label` | 입력 요소에 `label`이 연결됐는가 |
| `layout-result` | 항목이 의도한 행·열로 놓였는가 |

여기에 세 가지 장치를 더 걸었습니다.

- **스키마 검증**이 저장 전에 목록 밖 유형을 거부합니다. 프롬프트로 부탁하는 것이 아니라 코드가 막습니다
- **판정 로직은 `type`에 대응하는 고정 코드**가 수행합니다. AI가 쓴 설명문(`desc`)은 화면에만 쓰고 판정에 관여시키지 않습니다
- **프롬프트에 주입하는 유형 목록과 검증용 열거형이 같은 상수에서 파생**됩니다. 둘을 따로 두면 중복이 문서에서 코드로 자리만 옮깁니다

애매한 것은 필수에서 빼 **권장**으로 내립니다. 통과시키되 대안을 안내합니다.

### 화면 문구는 태그 이름을 그대로 씁니다

"대체 텍스트"가 아니라 `alt`, "최상위 제목"이 아니라 `h1`로 씁니다. 학습자가 검색하고 코드에 입력하는 말과 화면에 보이는 말이 같아야 하기 때문입니다. `alt`를 검색하면 바로 쓸 수 있는 문서가 나오지만 "대체 텍스트"로는 접근성 이론 문서가 나옵니다.

AI가 만드는 `desc`와 `hints`는 매번 달라져 전수 검사가 불가능하므로, 프롬프트에 같은 규칙을 넣어 생성 단계에서 통제합니다. 다만 **구조 분석(1단계)은 예외**입니다. 태그 선택이 학습자의 판단 영역이라 분석이 태그명을 쓰지 못하게 막아 두었고, 그 규칙이 우선합니다.

### `accept`에 여러 해석을 나열합니다

상품 6개가 3열 2행으로 놓인 시안에서, 목록 구조는 **`li` 6개짜리 `ul` 1벌**일 수도 **`li` 3개짜리 `ul` 2벌**일 수도 있습니다. 둘 다 맞습니다.

기대값을 하나로 고정하면 다른 쪽을 오답 처리합니다. 그래서 `list-grouping`은 가능한 해석을 모두 `accept` 배열에 담고 하나라도 맞으면 통과시킵니다.

반대로 `layout-result`는 해석이 갈리면 안 되는 유형이라 정확히 하나만 받습니다. 초기에 AI가 `1열 3행 + 행 내부 2열` 같은 **DOM 중첩 구조**를 기대값으로 쓰는 문제가 있었는데, 이는 해석 차이가 아니라 "배치는 결과로만 기술한다"는 규칙 위반이었습니다. 기대값을 말단 요소의 기하로만 쓰도록 강제해 해소했습니다.

## 측정 결과

브라우저에서 실제로 렌더해 측정합니다. jsdom 계열은 `getBoundingClientRect()`가 0을 반환해 `layout-result`를 검증할 수 없습니다 — 오류 없이 조용히 전부 통과하므로 더 위험합니다.

| 지표 | 결과 |
|---|---|
| **오탐** (정답을 오답 처리) | **0 / 12** |
| **미탐** (오답을 통과 처리) | **0 / 24** |
| 회차 간 조건 집합 일치 | 3회차 모두 동일 |
| 모범 예시가 자기 조건 충족 | 11 / 11 (실제 시안) |

오탐 12건은 **시안만 보고 작성한 정답 코드 4벌**입니다. 조건을 보고 짠 코드가 아니라 학습자와 같은 조건에서 쓴 코드여야 오탐 측정이 성립합니다. 모범 예시는 조건을 보고 만든 것이라 따로 집계했습니다.

작성 과정에서 **눈으로는 통과로 보이던 정답 두 벌이 실제로는 시안을 재현하지 못한 것**을 측정이 잡아냈습니다. 로고를 `h2`로 쓴 것, `inline-block` 사이 공백 때문에 3열이 깨진 것입니다.

## 구조적 제약과 근거

고칠 수 있는데 안 한 것이 아니라, **고치면 다른 곳이 나빠지는** 것들입니다.

### 시안 종횡비 1:5 상한

세로가 가로의 5배를 넘는 시안은 등록을 막습니다. 독립된 두 제약이 거의 같은 선에서 만납니다.

- API가 한 변 8000px 초과를 거부합니다. 저장 폭 1600px 기준으로 **비 5.0**
- 분석 모델이 긴 변을 2576px로 줄여 봅니다. 따라서 **모델이 보는 가로 = 2576 ÷ 종횡비**이고, 이 값은 리사이즈로 바꿀 수 없습니다. 본문을 읽으려면 500px가 필요해 **비 5.15**

실측입니다. 비 4.4인 시안(1920×8486)은 모델이 583px로 보고 상품명과 버튼 문구까지 정확히 읽었습니다. 비 14.1인 시안(1920×27108)은 183px로 보고 **구조 트리에 텍스트 주장이 하나도 없었으며**, 구역을 내용이 아니라 색으로 불렀습니다("주황 띠 안내"). 검증한 3개 구역의 이름과 구조가 모두 실제와 달랐습니다.

시안을 세로로 잘라 여러 장으로 보내면 넘을 수 있으나 v1 범위 밖입니다.

### `form-label`의 공허 통과

답안에 입력 요소가 하나도 없으면 `form-label`이 통과합니다. `image-alt`도 이미지가 없거나 `alt=""`이면 통과합니다.

필수 조건이 **구조 패턴만 기술하고 특정 요소의 존재를 요구하지 않기** 때문입니다. 이는 `target`을 판정에서 제외한 결정의 귀결이고, 그 결정이 오탐 0/12를 만든 근거입니다. 되돌리면 오탐이 늘어납니다. **미탐을 감수하는 쪽**이 이 도구의 원칙에 맞습니다.

다만 `layout-result`와 `list-grouping`이 반복 항목의 개수와 배치를 요구하므로, 구역의 주요 구조를 통째로 빠뜨리는 것은 여전히 걸립니다. 누락이 통과하는 범위는 조건이 걸리지 않은 개별 요소로 한정됩니다.

### 통짜 모드 구역 수 상한 5개

시안 전체를 한 번에 작성하는 모드입니다. 11구역 시안으로 끝까지 돌려 본 결과 학습 흐름이 성립하지 않았습니다.

| | 구역별 | 통짜 |
|---|---|---|
| 필수 조건 | 30개를 11번에 분산 | 16개를 한 번에 |
| 총 시도 | 33회 | 3회 |
| 실패 피드백 | 최대 5건 | 16건 동시 |
| 모범 예시 | 최대 2,343자 | 16,937자 |

시도 3회를 조건 16개가 공유해 사실상 세 번 안에 전부 맞혀야 하고, 회차별 힌트가 조건마다 따로 오르지 못합니다. **조건은 30개에서 16개로 성겨지는데 난이도는 오릅니다.**

모드 자체가 아니라 규모가 문제이므로 규모만 제한합니다. 4구역 시안은 통짜로도 조건 8개, 예시 4,013자로 감당할 수준이었습니다.

### 그 밖에

- **이미지 자리표시** — 학습자에게는 쓸 이미지 파일이 없어 `/placeholder/400x300.svg`를 앱이 내줍니다. `data:` URL도 검토했으나 가장 짧게 만들어도 123자, 크기 라벨을 넣으면 264자라 `src` 값이 코드를 덮습니다
- **미리보기에 스타일을 주입하지 않습니다** — 리셋 CSS도 넣지 않습니다. 학습자가 브라우저 기본 스타일 위에 자기 CSS만 얹힌 상태를 관찰해야 합니다. 판정용 문서도 같습니다

## 기술 스택

| 항목 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js 16 (App Router) | Route Handler로 AI 호출 프록시 |
| 언어 | TypeScript | 판정 조건 구조가 깊어 타입 필요 |
| 스타일 | Tailwind CSS v4 | 색은 전부 CSS 변수 |
| 에디터 | CodeMirror 6 | 확장 직접 조립, `basicSetup` 미사용 |
| 코드 렌더링 | iframe | `allow-same-origin` 단독 + CSP `script-src 'none'` |
| 저장 | IndexedDB | 시안 이미지, 분석 결과, 진행 상태 |
| AI | Claude Opus 5 | 서버 측 Route Handler에서만 호출 |
| 배포 | 가비아 클라우드 | Nginx 앞단, 타임아웃 300초 |

**iframe 격리** — `allow-scripts`를 주지 않으므로 인라인 `<script>`, 이벤트 핸들러, `javascript:` URL이 모두 실행되지 않습니다. 문서가 능동적으로 할 수 있는 일이 없어 오리진을 열어도 안전하며, `allow-same-origin` 단독으로 부모가 `contentDocument`를 읽어 측정합니다. 측정 스크립트를 주입할 필요가 없습니다.

판정용 iframe을 `display:none`으로 숨기면 **모든 측정값이 0이 되어 배치가 틀린 코드도 전부 통과합니다.** 오류 없이 조용히 통과하므로 화면 밖 배치를 씁니다.

**AI 호출** — 구조 분석 1회, 조건·예시 생성은 구역마다 1회씩입니다. 구역 전체를 한 요청에 담으면 11구역 시안에서 290초가 걸려 배포 환경의 실행 시간 한도를 넘습니다. 구역 단위로 나누면 **한 요청의 시간이 구역 수와 무관해집니다**(약 55초). 응답은 이미지 해시와 프롬프트 판본으로 캐시해 재분석 시 호출하지 않습니다.

## 개발

```bash
npm run dev
```

http://localhost:3000 에서 확인합니다. `ANTHROPIC_API_KEY`를 `.env.local`에 둡니다.

`/dev/verify`에 판정 엔진 검증 화면이 있습니다. 스키마 검증, 판정용 문서, 유형별 판정, 결합 판정, 실패 문구, 확인 결과 전이, 8.2 정확도 측정, 이미지 경로 영향을 한 화면에서 돌립니다.

### `predev` / `prebuild` 스크립트에 관하여

작업 경로가 exFAT 볼륨이라 macOS가 파일마다 AppleDouble 메타데이터 파일(`._*`)을 만듭니다. Turbopack은 `.next` 캐시 디렉터리의 파일명을 숫자로 파싱하므로 이 파일이 있으면 `next dev`와 `next build` 모두 실패합니다. 두 스크립트에서 이를 정리합니다. 리눅스 환경에서는 대상 파일이 없어 무해하게 통과합니다.

## 디렉터리

```
app/            라우트, API, 전역 스타일
components/     화면 구성 요소 (dev/ 는 검증 화면)
lib/ai/         프롬프트, API 호출, 응답 캐시
lib/judging/    조건 유형, 스키마 검증, 판정 로직, 피드백
lib/learning/   학습 세션, 확인 결과 전이, 확대·축소
lib/storage/    저장 계층
lib/korean.ts   조사 처리 (받침에 따라 은/는·이/가 선택)
fixtures/       정답·위반 코드, 회차별 AI 조건
docs/PRD.md     사양과 설계 근거
docs/archive/   단계별 구현 요청서 기록
```

문서는 파일명에 버전을 붙이지 않고 하나로 유지합니다. 변경 이력은 Git 커밋에 남깁니다.

저장소 접근은 `lib/storage/` 안에만 두고 컴포넌트에서 직접 호출하지 않습니다. 저장소 교체를 위해 인터페이스는 Promise 반환으로 통일합니다.
